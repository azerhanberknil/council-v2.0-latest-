# Build Guide

## Development

API:

```powershell
npm.cmd run api
```

Android emulator:

```powershell
npm.cmd run android
```

Web:

```powershell
npm.cmd run web
```

## Web export

```powershell
npm.cmd run export:web
```

The static web output is generated by Expo. Host it behind HTTPS and point it to a deployed Council API URL:

```text
EXPO_PUBLIC_COUNCIL_API_URL=https://your-api.example.com
```

Local preview:

```powershell
.\START_COUNCIL_WEB.cmd
```

Open `http://localhost:8787`. Do not open `dist/index.html` directly; browser `file://` mode cannot resolve the Expo asset paths correctly.

## Android production build

Install and configure EAS:

```powershell
npm.cmd install --save-dev eas-cli
npx.cmd eas login
npx.cmd eas build:configure
npx.cmd eas build --platform android
```

For local debug on the open Pixel emulator:

```powershell
npm.cmd run android
```

## iOS production build

Requires Apple Developer Program access and macOS/Xcode for local native builds, or EAS cloud build:

```powershell
npx.cmd eas build --platform ios
```

Apple purchases are intentionally disabled in the current codebase. Add StoreKit product IDs in App Store Connect before wiring production purchases.

## Windows `.exe`

Expo mobile does not output a Windows `.exe`. The practical route is:

1. Export web:

```powershell
npm.cmd run export:web
```

2. Wrap the web build with Electron or Tauri.
3. Sign the installer before distribution.

This should be a separate packaging step after the mobile MVP is stable.

## macOS desktop

Options:

- Use the web/PWA build in a browser.
- Wrap the web build with Electron/Tauri and ship `.dmg`.
- Build a separate native macOS app after the iOS version is validated.

## Backend deployment

`server/server.mjs` is a small Node HTTP API. For production:

- Deploy behind HTTPS.
- Store `GEMINI_API_KEY` in platform secrets.
- Add rate limits.
- Add auth/session validation.
- Add server logs without storing sensitive prompt text by default.
